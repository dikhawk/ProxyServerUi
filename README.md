# ProxyServerUi (Proxy Local Rotator & Checker)

Десктопное приложение на Python (PyQt6) для Linux/Unix, предоставляющее локальный прокси-сервер с автоматической ротацией трафика, отказоустойчивостью (failover), параллельной проверкой пула прокси (чекером), определением GeoIP и поддержкой авторизации.

---

## 🎯 Назначение

Приложение решает задачу стабильного и непрерывного выхода в сеть через пул внешних прокси-серверов. 

Вместо ручного переключения прокси в браузере или в коде ваших парсеров/скриптов, вы настраиваете клиенты на единую точку входа:
```text
http://127.0.0.1:8080   или   socks5://127.0.0.1:8080
```

Локальный сервер берет на себя всю внутреннюю работу:
* Маршрутизирует клиентские запросы через пул живых внешних прокси.
* При падении или таймауте внешнего узла **на лету** повторяет запрос через следующий прокси без разрыва сессии клиента (transparent failover).
* Регулярно актуализирует базу, проверяет задержки (пинг), исключает недоступные ноды и фильтрует трафик по протоколам и странам.

## 🚀 Функциональность

### 1. Локальный прокси-сервер и умная ротация
* **Поддержка протоколов:** HTTP-запросы и туннелирование HTTPS/TCP через метод `CONNECT`.
* **Поддержка внешних апстримов:** HTTP, HTTPS, SOCKS4, SOCKS5 (включая авторизацию по логину и паролю).
* **Failover без таймеров:** если апстрим-прокси не ответил или оборвал соединение, сервер фиксирует сбой, берёт следующий рабочий узел из очереди и повторяет запрос.
* **Автоматическая остановка:** если весь рабочий пул выходит из строя (`Dead`), сервер безопасно останавливается и информирует пользователя.

### 2. Сбор и управление базой прокси
* **Импорт из файлов:** загрузка списков из локальных `.txt` файлов через системное диалоговое окно.
* **Сбор из сети (Harvesting):** автоматическое асинхронное скачивание списков прокси по URL из конфигурации.
* **Поддержка форматов:**
  * `IP:Port`
  * `IP:Port:User:Pass`
  * `protocol://IP:Port`
  * `protocol://User:Pass@IP:Port`
* **Умная дедупликация:** при повторном импорте существующие прокси не перезаписываются, сохраняя историю проверок, задержки и статистику сбоев.
* **Хранение данных:** персистентное сохранение базы в `proxies_database.csv`.
* **Очистка базы:** полная очистка таблицы и CSV-файла с подтверждением через диалоговое окно.

### 3. Проверка и валидация (Proxy Checker & GeoIP)
* **Асинхронная проверка:** параллельное тестирование пула на базе `httpx`, `httpx-socks` и `asyncio.Semaphore`.
* **Мульти-URL тестирование:** проверка доступности по набору целевых URL (например, Google, Httpbin и др.).
* **Замер пинга:** измерение реального времени отклика в миллисекундах.
* **GeoIP-детекция:** автоматическое определение страны расположения прокси через сервис `ip-api.com`.
* **Учёт отказов:** подсчёт неудачных попыток (`fail_count`). При достижении порога `max_dead_attempts` узел получает статус `Dead` с фиксацией времени.
* **Сброс статистики:** возможность вернуть узлы со сбоями обратно в строй одной кнопкой.

### 4. Фильтрация пула
* **По протоколу:** переключение активного пула между HTTP, HTTPS, SOCKS4, SOCKS5 через выпадающий список в интерфейсе.
* **По странам:** выбор предпочитаемых стран (ISO-коды) в настройках приложения.

### 5. Пользовательский интерфейс (GUI)
* Таблица со статусами, типами, пингом, локацией, счетчиками сбоев и датами.
* Корректная сортировка столбцов (числовая сортировка для пинга и счетчика сбоев).
* Консоль логов в реальном времени с цветовой подсветкой (информационные сообщения, успешный запуск зеленым, ошибки и падения красным).
* Модальное окно настроек параметров сервера, таймаутов, тестовых ссылок и стран.
* Блокировка элементов управления при активном сервере для предотвращения гонок состояний.

## 🛠 Архитектура и стек технологий

Проект построен по принципам многослойной архитектуры (Layered Architecture) и паттерна MVP/Controller с Dependency Injection:

* **Domain Layer (`src/domain/`):** сущности `ProxyItem`, перечисления `ProxyProtocol`, `ProxyStatus`, `AppState`, модель конфигурации `AppConfig`.
* **Data Layer (`src/data/`):** репозитории `ConfigRepository` (JSON), `ProxyRepository` (CSV + in-memory словарь) и парсер `ProxyParser`.
* **Network Layer (`src/network/`):** сетевые сервисы `ProxySourceFetcher`, `ProxyCheckerService`, `ProxyRotationManager`, `LocalProxyServer` (на `python-socks`).
* **Presentation Layer (`src/presentation/`):** связующий контроллер `AppController`.
* **UI Layer (`src/ui/`):** главное окно `MainWindow`, виджеты `ControlPanelWidget`, `LogConsoleWidget`, диалог `SettingsDialog`, модели таблиц `ProxyTableModel` и `ProxySortFilterModel`.

**Стек библиотек:**
* Python 3.10+
* `PyQt6` — графический интерфейс
* `qasync` — интеграция Qt Event Loop с асинхронным циклом `asyncio`
* `httpx`, `httpx-socks` — асинхронные HTTP/SOCKS запросы для чекера и харвестера
* `python-socks[asyncio]` — сетевое проксирование и TCP-туннелирование для локального сервера

## 📦 Установка

1. **Клонируйте репозиторий или перейдите в папку проекта:**
   ```bash
   cd ProxyServerUi
   ```

2. **Создайте виртуальное окружение Python:**
   ```bash
   python -m venv venv
   ```

3. **Активируйте виртуальное окружение и установите зависимости:**
   ```bash
   ./venv/bin/pip install --upgrade pip
   ./venv/bin/pip install -r requirements.txt
   ```

## ⚙️ Конфигурация

Параметры сохраняются в файле `config.json` в корневой директории:

| Параметр | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `proxy_sources` | Список URL-адресов для скачивания списков прокси | Список публичных репозиториев |
| `local_port` | Порт локального прокси-сервера (`127.0.0.1:<port>`) | `8080` |
| `preferred_countries` | Список разрешенных стран (ISO 3166-1 alpha-2) | `["US", "DE", ...]` (или пустой для всех) |
| `test_urls` | Список URL для проверки доступности прокси чекером | `["https://gemini.google.com/"]` |
| `connection_timeout_ms`| Таймаут на установку TCP-соединения (мс) | `3000` |
| `response_timeout_ms`  | Таймаут на получение ответа от целевого сервера (мс) | `5000` |
| `max_dead_attempts`    | Порог сбоев, после которого прокси переходит в `Dead` | `5` |

Конфигурацию можно редактировать вручную через `config.json` либо через кнопку **[⚙️ Настройки]** в графическом интерфейсе приложения.
