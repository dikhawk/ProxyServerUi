# Техническое задание и ООП-архитектура: "Proxy Local Rotator & Checker"

**Целевая ОС:** Linux (Manjaro)  
**Язык и стек:** Python 3.10+, PyQt6, `qasync`, `httpx`, `httpx-socks`, `python-socks[asyncio]`  
**Архитектурный паттерн:** Layered Architecture (Domain / Data / Network / UI) + MVP / Контроллер с внедрением зависимостей (Dependency Injection).

---

## Часть 1. Архитектурные принципы и структура директорий (Строгие правила для LLM)

1. **Принцип единой ответственности (SRP) и модульности:** Каждый основной класс должен находиться в своем собственном файле. Запрещено объединять UI, сетевую логику и хранение данных в одном модуле.
2. **Слабая связность (Decoupling):** Слой `network` и слой `data` ничего не знают о `PyQt6`. Общение между бизнес-логикой и UI происходит через контроллер (`AppController`), колбэки или Qt-сигналы на уровне презентационного слоя.
3. **Строгая типизация (Type Hints):** Все методы, атрибуты классов и возвращаемые значения должны быть аннотированы с помощью модуля `typing`.

## Часть 2. Функциональная спецификация и обязанности классов

### 1. Слой `domain` (Модели и перечисления)
* **`enums.py`:**
  * `ProxyProtocol(str, Enum)`: `HTTP = "http"`, `HTTPS = "https"`, `SOCKS4 = "socks4"`, `SOCKS5 = "socks5"`.
  * `ProxyStatus(str, Enum)`: `ACTIVE = "Active"`, `DEAD = "Dead"`, `CHECKING = "Checking"`, `UNTESTED = "Untested"`.
  * `LogLevel(str, Enum)`: `INFO = "info"` (стандартный цвет), `SUCCESS = "success"` (зеленый), `ERROR = "error"` (красный).
  * `AppState(str, Enum)`: `IDLE = "Idle"`, `RUNNING = "Running"`, `CHECKING = "Checking"`.
* **`proxy_item.py` (`class ProxyItem`):**
  * Атрибуты: `protocol: ProxyProtocol`, `host: str`, `port: int`, `username: Optional[str] = None`, `password: Optional[str] = None`, `location: str = "Unknown"`, `status: ProxyStatus = ProxyStatus.UNTESTED`, `ping: Optional[int] = None`, `url_status: str = "-"`, `added_at: str`, `fail_count: int = 0`, `dead_since: str = ""`.
  * Методы бизнес-логики внутри класса:
    * `unique_key -> str`: возвращает `f"{self.protocol.value}://{self.host}:{self.port}"`.
    * `upstream_url -> str`: возвращает полный URL с авторизацией (`protocol://user:pass@host:port` или `protocol://host:port`).
    * `register_success(ping_ms: int, url_status: str, location: Optional[str] = None) -> None`: сбрасывает `fail_count = 0`, очищает `dead_since = ""`, ставит `status = ProxyStatus.ACTIVE`, обновляет `ping` и `location` (если передан).
    * `register_failure(max_attempts: int, url_status: str = "FAIL") -> bool`: увеличивает `fail_count += 1`. Если `fail_count == 1`, фиксирует текущее время в `dead_since`. Если `fail_count >= max_attempts`, переводит `status = ProxyStatus.DEAD` и возвращает `True` (прокси окончательно мертв).
    * `mark_dead(max_attempts: int, url_status: str = "FAIL") -> None`: форсированно переводит прокси в статус `ProxyStatus.DEAD`, устанавливает `fail_count = max_attempts`, фиксирует метку времени в `dead_since` (если она еще не задана) и задает статус `url_status`. Используется чекером при однократной проверке прокси на доступность целевых ресурсов.
    * `reset_statistics() -> None`: обнуляет `fail_count = 0`, `dead_since = ""`, переводит статус в `ProxyStatus.ACTIVE`.
* **`app_config.py` (`class AppConfig`):**
  * Атрибуты: `proxy_sources: list[str]`, `local_port: int = 8080`, `preferred_countries: list[str]`, `test_urls: list[str]`, `connection_timeout_ms: int = 3000`, `response_timeout_ms: int = 5000`, `max_dead_attempts: int = 5`.
  * Метод `validate() -> tuple[bool, str]`: проверяет корректность `test_urls` (схема `http`/`https`, наличие домена) и диапазоны таймаутов/портов.

### 2. Слой `data` (Парсинг и хранение)
* **`proxy_parser.py` (`class ProxyParser`):**
  * Отвечает за парсинг сырых строк (`IP:Port`, `IP:Port:User:Pass`, `protocol://IP:Port`, `protocol://User:Pass@IP:Port`) в объекты `ProxyItem`.
* **`config_repository.py` (`class ConfigRepository`):**
  * Загружает и сохраняет `AppConfig` в локальный файл `config.json` рядом с программой. При отсутствии файла создает его с дефолтными параметрами.
* **`proxy_repository.py` (`class ProxyRepository`):**
  * Хранит коллекцию прокси в словаре `_items: dict[str, ProxyItem]`.
  * Отвечает за загрузку при старте и сохранение в локальный файл `proxies_database.csv`.
  * Метод `add_or_merge(new_items: list[ProxyItem]) -> int`: автоматическая дедупликация. Если `unique_key` уже есть в базе — старый объект **не перезаписывается** (сохраняется вся его статистика, пинг, дата добавления и сбои). Добавляются только новые узлы.
  * Метод `remove_items(items: list[ProxyItem]) -> int`: удаляет переданные прокси из словаря по их `unique_key`, перезаписывает `proxies_database.csv` и возвращает количество удаленных элементов. Используется для ручного удаления выбранных строк.
  * Метод `remove_dead() -> int`: фильтрует коллекцию и удаляет все прокси со статусом `ProxyStatus.DEAD`, перезаписывает `proxies_database.csv` и возвращает количество удаленных узлов.
  * Метод `clear_all() -> None`: полностью очищает словарь `_items` в памяти и перезаписывает пустой `proxies_database.csv` (оставляя только заголовки).
  * Методы выборки:
    * `get_available_protocols() -> list[str]`: возвращает уникальные типы протоколов, имеющиеся в базе, для заполнения `QComboBox`.
    * `get_available_countries() -> list[str]`: возвращает уникальные коды стран (`location`) из базы для окна настроек.
    * `get_working_pool(protocol: str, countries: list[str]) -> list[ProxyItem]`: возвращает прокси со статусом `Active` (и `Untested`), отфильтрованные по выбранному протоколу и предпочитаемым странам (если список стран пуст — берет все страны).

### 3. Слой `network` (Сетевые сервисы и детальное логирование)
* **`source_fetcher.py` (`class ProxySourceFetcher`):**
  * Асинхронно через `httpx` скачивает текстовые списки по всем URL из `proxy_sources` конфига и передает их в `ProxyParser`.
  * При скачивании каждого источника логирует URL, HTTP-код ответа (например, `HTTP 200`) или точную причину ошибки подключения.
* **`proxy_checker.py` (`class ProxyCheckerService`):**
  * Асинхронно проверяет список `ProxyItem` (с ограничением конкурентности `asyncio.Semaphore(50)`).
  * Использует `connection_timeout_ms` и `response_timeout_ms` из `AppConfig` (переводя их в секунды для `httpx.Timeout`).
  * **Однократная проверка пула (`single_check: bool = True`):**
    * При нажатии кнопки «⚡ Проверить» чекер выполняет однократную проверку каждого узла на доступность ресурсов из настроек (`test_urls`).
    * Если запрос вернул успешный статус (`200 <= status_code < 400`), прокси сразу считается полностью рабочей: переводится в статус `ProxyStatus.ACTIVE`, пинг фиксируется, а счетчик `fail_count = 0`.
    * Если запрос завершился ошибкой, таймаутом или сбоем подключения, прокси немедленно переводится в `ProxyStatus.DEAD`, счетчик сбоев выставляется в лимит `max_dead_attempts`, фиксируются `dead_since` и `url_status = "FAIL"` (через метод `item.mark_dead`).
  * **Прерывание проверки (Stop Check):** поддерживает отмену процесса (`cancel()`), устанавливая `_is_cancelled = True` и отменяя все активные подзадачи `asyncio.Task`, возвращая UI в исходное состояние.
  * **Отказоустойчивое определение местоположения (Resilient GeoIP с кешированием):**
    * Для решения проблемы неопределения страны у части IP реализована многоуровневая схема с in-memory кешированием `_GEOIP_CACHE[host]`.
    * Сначала выполняется запрос через сам рабочий прокси (`http://ip-api.com/json/?fields=countryCode`).
    * Если прокси не ответил или запрос завершился ошибкой, срабатывает fallback — прямой опрос пула независимых GeoIP-сервисов (`https://api.country.is/{host}`, `https://ipwho.is/{host}`, `http://ip-api.com/json/{host}?fields=countryCode`, `https://freeipapi.com/api/json/{host}`).
    * Страна определяется даже для не ответивших прокси, что исключает появление пустых локаций и статусов "Unknown" в базе.
  * Для каждого запроса к тестовому URL передает в колбэк лога детальную информацию:
    * При успехе: `[Чекер] Прокси {ip}:{port} -> {url} | Статус: {status_code} ({ping} мс)`
    * При сбое: `[Чекер] Ошибка {ip}:{port} -> {url} | Причина: {status_code или текст исключения: Timeout / ConnectionError / ProxyError}` (красным цветом).
* **`rotation_manager.py` (`class ProxyRotationManager`):**
  * Управляет рабочей очередью (`collections.deque[ProxyItem]`) во время работы локального прокси.
  * Инициализируется отфильтрованными живыми прокси (по выбранному в UI протоколу и выбранным в настройках странам).
  * Метод `get_current_proxy() -> Optional[ProxyItem]`: возвращает первый рабочий прокси из очереди.
  * Метод `active_count() -> int`: возвращает текущее количество активных живых прокси в очереди.
  * Метод `report_failure(proxy: ProxyItem) -> bool`: вызывает `proxy.register_failure(max_attempts)`. Если лимит не превышен — перемещает прокси в конец очереди (`deque`). Если лимит достигнут (`Dead`) — удаляет его из рабочей очереди.
* **`local_server.py` (`class LocalProxyServer`):**
  * Поднимает локальный прокси-сервер на `127.0.0.1:local_port` без авторизации.
  * Принимает клиентские подключения (HTTP-запросы и метод `CONNECT` для HTTPS/TCP) и маршрутизирует их через прокси из `ProxyRotationManager` с помощью `python-socks`.
  * **Счетчик рабочих прокси в реальном времени:** принимает колбэки `on_pool_updated(active: int, total: int)` и `on_proxy_status_changed(item: ProxyItem)`. При запуске сервера фиксирует общий размер пула `total_proxies`. При каждом сбое, если прокси исчерпал лимит сбоев и помечается мертвым, сервер немедленно вызывает колбэки, чтобы счетчик активных прокси в UI и строка в таблице обновились моментально без задержек.
  * **Гарантированная остановка сервера:** при вызове `stop()` сервер переводит `is_running = False`, отменяет все активные клиентские задачи (`_active_tasks`), закрывает сетевой сокет `asyncio.Server` и ожидает его закрытия (`wait_closed()`), освобождая порт.
  * **Детальное логирование трафика в реальном времени:**
    * Для обычных HTTP-запросов парсит целевой URL и первую строку ответа от сервера, выводя в лог: `Запрос -> {target_url} через {proxy_ip}:{port} | Ответ: HTTP {status_code}`.
    * Для HTTPS-туннелей (`CONNECT host:443`) логирует установку туннеля к целевому хосту/URL: `Туннель -> {target_host}:{target_port} через {proxy_ip}:{port} | Статус: 200 Connection Established`.
    * При любой ошибке подключения или таймауте выводит в лог красным цветом целевой URL/хост и точную причину: `Ошибка обращения к {target_url} через {proxy_ip}:{port} | Причина: {Timeout / Connection Reset / HTTP 502 и т.д.} (Сбои: {fail_count}/{max})`.
  * **Failover «На лету» (без фоновых таймеров):** Отдельный фоновый чекер по таймеру отсутствует. Если при обработке клиентского запроса внешний прокси выдал ошибку или таймаут, сервер вызывает `rotation_manager.report_failure()`, берет следующий прокси из очереди и повторяет попытку соединения без разрыва клиентской сессии.
  * **Авто-остановка при гибели пула:** Если в `ProxyRotationManager` не осталось живых прокси (все перешли в `Dead`), локальный сервер автоматически останавливается, разблокирует UI и выводит в лог критическую ошибку красным цветом.

### 4. Слой `ui` и `presentation` (Интерфейс и Управление)
* **Главное окно (`MainWindow`) включает:**
  1. `ControlPanelWidget`:
     * `[📁 Загрузить файл]` — открывает системное диалоговое окно выбора файла (`QFileDialog.getOpenFileName` с фильтром `Text Files (*.txt);;All Files (*)`), читает выбранный файл, парсит строки и добавляет их в базу с дедупликацией.
     * `[🔄 Обновить]` — скачивает списки прокси по URL из конфига.
     * `[⚡ Проверить]` / `[⏹️ Стоп]` — запускает однократную проверку пула. В процессе проверки кнопка меняет текст на `[⏹️ Стоп]`, позволяя пользователю прервать проверку в любой момент без зависаний.
     * `[🧹 Сброс ст.]` — сбрасывает счетчики ошибок (`fail_count = 0`) и возвращает все прокси в строй.
     * `[🗑️ Очистить]` — полностью очищает список прокси (с диалогом подтверждения `QMessageBox.question`), удаляет записи из таблицы и очищает CSV-файл, а также сбрасывает селектор протоколов `QComboBox`.
     * `[❌ Удалить]` — вручную удаляет выбранные пользователем в таблице прокси из базы данных и CSV-файла (также доступно через контекстное меню таблицы и клавишу `Delete`).
     * `[💀 Удалить Dead]` — в один клик удаляет из базы данных и таблицы все нерабочие («мертвые») прокси со статусом `Dead`.
     * Выпадающий список протоколов `QComboBox` (динамически обновляется при загрузке или очистке списка).
     * Кнопка `[⚙️ Настройки]`.
     * Текстовый индикатор статуса:
       * При запущенном сервере отображает реальное число работающих прокси в пуле: `🟢 Работает (активно: {active}/{total})`. При переходе любого узла в `Dead` счетчик тут же декрементируется.
       * При проверке пула: `⚡ Проверка...` (оранжевый цвет `#f39c12`).
       * При остановленном сервере: `🔴 Остановлен` (красный цвет `#e74c3c`).
     * Метод `set_active_proxy_count(active: int, total: int)`: динамически обновляет текст и цвет статуса.
  2. `QTableView` + `ProxyTableModel` + `ProxySortFilterModel`: таблица со столбцами (`Тип`, `Адрес`, `Локация`, `Статус`, `Пинг (мс)`, `URL Статус`, `Добавлен`, `Сбои`, `Мертв с`) с поддержкой вертикальной/горизонтальной прокрутки (Scrollbar) и корректной сортировки по клику на заголовки столбцов.
     * В `ProxyTableModel` реализован метод `set_max_attempts(max_attempts: int)`: при смене лимита сбоев в настройках (`max_dead_attempts`) модель немедленно обновляет отображение колонки «Сбои» (`fail_count/max_attempts`) для всех строк таблицы через сигнал `dataChanged` (значение моментально меняется, например с `0/5` на `0/10`).
     * В `MainWindow` реализована поддержка множественного выделения строк, контекстное меню таблицы (CustomContextMenu) с пунктом «Удалить выбранные», обработчик нажатия клавиши `Delete` и метод `get_selected_proxies() -> list[ProxyItem]`.
  3. `LogConsoleWidget`: лог-консоль (`QTextEdit`, Read-Only) с цветовой индикацией:
     * **Стандартный цвет:** обычные информационные события, обращения к URL и полученные коды ответа (`200 OK` и др.).
     * **Зеленый цвет (`#2ecc71`):** успешный старт локального прокси с выводом готовой ссылки для подключения (например: `Локальный прокси запущен: socks5://127.0.0.1:8080`).
     * **Красный цвет (`#e74c3c`):** ошибки обращения к URL с указанием причины/кода ошибки, сбои переключения прокси, остановка сервера из-за того, что все прокси мертвы.
  4. Главная кнопка внизу окна: `[Запустить локальный прокси]` / `[Остановить локальный прокси]`:
     * При нажатии кнопки остановки запущенный локальный сервер гарантированно останавливается: завершаются активные клиентские сессии, закрывается сетевой порт, база данных сохраняется в CSV, UI возвращается в состояние `IDLE`, а кнопки управления немедленно разблокируются.
* **Машина состояний (State Machine):**
  * В режиме `RUNNING` блокируются (`setEnabled(False)`) кнопки: `Загрузить файл`, `Обновить`, `Проверить`, `Сброс статистики`, `Очистить`, `Удалить`, `Удалить Dead`, селектор типа протокола `QComboBox` и кнопка настроек `⚙️`. Активна только кнопка остановки сервера.
  * В режиме `CHECKING` кнопка `Проверить` превращается в `[⏹️ Стоп]` и остается активной, остальные кнопки операций блокируются во избежание конфликтов данных.

## Часть 4. Поэтапный план реализации для LLM (От простого к сложному)

Реализуй проект строго итеративно, создавая каждый класс в отдельном файле согласно структуре из Части 1. После каждого этапа проверяй код юнит-тестами.

### Этап 1: Слой `domain` (Сущности и бизнес-правила)
1. Создай пакет `src/domain/`.
2. Реализуй `enums.py` (`ProxyProtocol`, `ProxyStatus`, `LogLevel`, `AppState`).
3. Реализуй `proxy_item.py` (`ProxyItem`) со всеми методами переходов состояний (`register_success`, `register_failure`, `reset_statistics`).
4. Реализуй `app_config.py` (`AppConfig`) с методом валидации URL и целочисленных параметров.
5. Проверка: напиши и запусти тест, проверяющий, что 5 вызовов `register_failure(max_attempts=5)` переводят прокси в `ProxyStatus.DEAD`, а `reset_statistics()` возвращает его в `ProxyStatus.ACTIVE` со счетчиком `0`.

### Этап 2: Слой `data` (Парсер и Репозитории)
1. Создай пакет `src/data/`.
2. Реализуй `proxy_parser.py` (`ProxyParser`) с поддержкой форматов без авторизации и с авторизацией (`IP:Port:User:Pass` и `protocol://User:Pass@IP:Port`).
3. Реализуй `config_repository.py` (`ConfigRepository`) для чтения и записи `config.json`.
4. Реализуй `proxy_repository.py` (`ProxyRepository`) с сохранением/загрузкой `proxies_database.csv`, методом полной очистки `clear_all()`, дедупликацией через словарь без перезаписи существующих прокси и методами фильтрации по протоколу и странам.
5. Проверка: протестируй парсинг разных строк, сохранение в CSV, слияние дублирующихся списков и полную очистку репозитория.

### Этап 3: Слой `network` — Чекер, Загрузчик и Менеджер Ротации
1. Создай пакет `src/network/`.
2. Реализуй `source_fetcher.py` (`ProxySourceFetcher`) для асинхронного скачивания списков по URL через `httpx` с логированием URL источника и HTTP-кода ответа или причины ошибки.
3. Реализуй `proxy_checker.py` (`ProxyCheckerService`) для мульти-URL проверки прокси (через `httpx` и `httpx-socks`), замера пинга в мс, определения страны (`location`) через GeoIP API и подробного логирования каждого проверяемого URL с кодом ответа или текстом ошибки.
4. Реализуй `rotation_manager.py` (`ProxyRotationManager`) на базе `collections.deque`, реализующий перемещение сбойного прокси в конец очереди и исключение мертвых прокси при достижении `max_dead_attempts`.

### Этап 4: Слой `network` — Локальный прокси-сервер с Failover и логами запросов
1. Реализуй `src/network/local_server.py` (`LocalProxyServer`).
2. Настрой асинхронный сервер (`asyncio.start_server`), который принимает соединения от локального клиента (HTTP и `CONNECT`) и туннелирует трафик через текущий прокси из `ProxyRotationManager` с помощью `python-socks`.
3. Добавь извлечение целевого URL/хоста и логирование результата обращения: к какому URL шел запрос, какой код ответа вернул сервер или по какой причине произошел сбой.
4. Реализуй цикл Failover «на лету»: при ошибке или таймауте подключения к внешнему прокси вызывай `rotation_manager.report_failure()`, отправляй детальное уведомление в лог красным цветом и мгновенно переключайся на следующий прокси из очереди.
5. Реализуй автоматическую остановку сервера с красным логом, если в `ProxyRotationManager` закончились живые прокси.

### Этап 5: Слой `ui` и `presentation` (Сборка PyQt6 и DI)
1. Создай пакет `src/ui/models/` и реализуй `ProxyTableModel` и `ProxySortFilterModel` (с корректной числовой сортировкой пинга и сбоев).
2. Создай пакет `src/ui/widgets/` и реализуй `ControlPanelWidget` (включая кнопки загрузки через системный чузер и очистки списка) и `LogConsoleWidget` (с поддержкой цветных логов).
3. Реализуй `src/ui/settings_dialog.py` (`SettingsDialog`) с динамическим списком чекбоксов стран из базы.
4. Реализуй `src/ui/main_window.py` (`MainWindow`).
5. Реализуй `src/presentation/app_controller.py` (`AppController`), связывающий сигналы UI (включая вызов `QFileDialog.getOpenFileName` для выбора `.txt` файла и `QMessageBox` для очистки базы), репозитории и сетевые сервисы, а также управляющий блокировкой кнопок в режиме `RUNNING`.
6. Собери точку входа `main.py` с инициализацией `qasync.QEventLoop` и создай `requirements.txt`.

### Этап 6: Дополнительный функционал, исправления и интеграционные тесты
1. **Ручное удаление выбранных прокси:**
